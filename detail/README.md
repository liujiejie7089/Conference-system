## 1. 项目定位

AIOA（Agent-era Office Automation）是基于智能体时代的协同办公平台，也是地级市 AI 公共服务平台的用户侧入口。产品形态为"**一套底座 + 四端**"，本仓库承担**一期客户端小程序（用户端）**的研发。

- **产品架构**：见《AI工作台AIOA产品架构概要方案.docx》（41 实体五域模型，V1.1 基线）
- **技术方案**：见《AIOA技术方案.docx》（六横两纵架构、8 微服务域、Agent Runtime）
- **一期范围**：见《AIOA实体分级与PoC验证计划.docx》（P0 = 12 实体，一期只验收 P0）
- **需求规格**：见《AIOA客户端小程序P0需求规格说明书.docx》（4 角色 / 6 步主链路 / 31 条 FR，M-O 分级）

## 2. 一期技术栈（约定，变更需评审）

| 层 | 选型 | 说明 |
|---|---|---|
| 客户端 | **uni-app（Vue 3 + TS）** | 一套代码三端（微信小程序 / H5 / App），微信小程序优先 |
| UI 组件 | uni-ui / uview-plus | 按原型视觉还原 |
| 状态管理 | Pinia | |
| 后端运行时 | **AgentScope 2.0（Python）** | Agent Runtime：感知-规划-执行-反思 + 审批卡点 |
| 服务框架 | FastAPI / Spring（按开发者熟悉度定） | BFF 网关 + 8 微服务域渐进落地 |
| 数据库 | PostgreSQL + Redis | 一期单库多 schema，预留租户隔离 |
| 部署 | Docker Compose（一期） | 二期迁政务云 K8s |

**一期后端只做 4 个最小服务**：会话服务、Agent Runtime（对接模型网关）、词元/账本记账服务、用户与租户服务。其余微服务域二期再拆。

## 4. UI 还原基准

`design/AIOA客户端小程序交互原型.html` 为**一期 UI 与交互的唯一基准**，浏览器直接打开即可体验。必须还原的交互点（对应 FR 编号见 P0 说明书）：

1. 会话流式输出（模拟 30ms 分片）→ 真实 SSE / WebSocket
2. 词元额度实时扣减显示（FR-C 类）
3. 引用溯源条（FR-D 类）
4. 敏感词触发审批卡点（FR-E 类，含通过/驳回/意见填写）
5. 技能表单动态渲染（FR-F 类）
6. 额度用尽三分支引导（升级会员 / 充值 / 切换免费模型）

原型中所有 mock 数据、文案、状态流转即为验收口径，不得自行删改交互流程。

## 5. 分支与协作规范

```
main        # 受保护：可运行、可演示的稳定版，只接受 PR 合入
develop     # 日常集成主干
feat/*      # 功能分支：feat/session-chat, feat/token-ledger ...
fix/*       # 修复分支
```

- Commit 信息格式：`[模块] 动作 描述`，如 `[会话] feat 支持流式输出中断`
- 每完成一条 FR 提交并在 commit 中注明 FR 编号（如 `FR-C01`）
- **里程碑验收**：每周五产出可运行 demo，产品方（左齐）按 P0 说明书的验收门禁逐条勾验
- 一期验收标准：31 条 FR 中所有 **M（Must）级**全部通过，O（Optional）级通过率 ≥ 60%

## 6. 里程碑建议（4 个月一期）

| 里程碑 | 周期 | 交付 |
|---|---|---|
| M1 骨架 | 第 1-3 周 | 工程搭建 + 四 Tab 页面骨架 + 原型视觉还原 + 登录 |
| M2 核心链路 | 第 4-8 周 | 会话建立 → 流式输出 → 词元记账 → 账本扣减 全链路跑通（接真实模型网关） |
| M3 安全闭环 | 第 9-11 周 | 敏感词 → 审批卡点 → 审批结果回注会话；技能表单 |
| M4 验收 | 第 12-16 周 | P0 12 实体全量 FR 联调 + 会员/支付入口 + 一期验收 |
